## Remaining Product Risks

- Admin employee management can add a display employee, but it does not yet create a login credential/PIN for that new employee. For now, add new employee credentials through code or a future admin PIN-management screen.
- Sessions are signed and expire, but there is no token revocation list yet. Rotating `SESSION_SECRET` or service-role secret invalidates sessions.
- PIN hashes are server-only in runtime, but fallback seed hashes live in the repository. This is acceptable for the current lightweight setup, but long term the `employee_credentials` Supabase setting should become the only credential source.
- Full database normalization is still future work; app state is currently stored in the Supabase `settings` JSON record.
